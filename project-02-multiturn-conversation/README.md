# Project 02 — Multi-Turn Conversation

A minimal educational GenAI project demonstrating how an LLM API maintains conversational context across turns by receiving the full message history with every request.

---

## Purpose

Large Language Models (LLMs) are stateless. When an API call completes, the model retains no internal memory of what was asked or answered. If a user asks "Explain RAG" in Turn 1, and then asks "Why is it useful?" in Turn 2, the model can only understand what "it" refers to if the application explicitly provides the prior dialogue.

This project demonstrates how conversational context is created and maintained by managing an in-memory message history list in the application and transmitting the complete history with every request.

---

## Core Concepts

### 1. System Message
The initial guiding prompt (`role: system`) that sets the persona, behavior guidelines, and tone of the AI assistant. It remains at the head of the message history.

### 2. User Message
Input sent by the human user (`role: user`). Each new input is appended to the message history.

### 3. Assistant Message
The output generated by the language model (`role: assistant`). Each response is appended to the message history so subsequent turns can reference it.

### 4. Message History
A linear list of message dictionaries maintained in memory:
```json
[
  {"role": "system", "content": "You are a helpful AI assistant..."},
  {"role": "user", "content": "Explain RAG."},
  {"role": "assistant", "content": "RAG stands for Retrieval-Augmented Generation..."},
  {"role": "user", "content": "Why is it useful?"}
]
```

### 5. Multi-Turn Conversation
An interactive dialogue consisting of multiple sequential back-and-forth exchanges between user and assistant.

### 6. Sending Conversation History with Every Request
Rather than sending only the latest query, the application submits the entire cumulative list of messages. This gives the model the complete transcript required to resolve pronouns, follow instructions, and maintain coherence.

### 7. Streamlit Session State
Streamlit executes Python scripts from top to bottom on each user interaction. `st.session_state` preserves the conversation history across reruns in memory without needing an external database.

### 8. OpenRouter
A unified API gateway that routes requests to various open-source and proprietary models (e.g., Llama 3, Mistral, Gemini, DeepSeek).

### 9. OpenAI-Compatible API
An industry-standard HTTP interface structure (`/chat/completions`) supported by OpenRouter, allowing standard client libraries like `openai` to interact with diverse models by simply updating the `base_url` to `https://openrouter.ai/api/v1`.

---

## Message Flow

```text
User message
  ↓
Add to history
  ↓
Send complete history to model (via OpenRouter)
  ↓
Model generates response
  ↓
Add assistant response to history
  ↓
Display conversation in Streamlit interface
```

## Local Setup Instructions

### 1. Activate the Root Virtual Environment

From the root `AI and LLM` folder in Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

### 2. Install Project Dependencies

```powershell
pip install -r project-02-multiturn-conversation\requirements.txt
```

### 3. Configure the OpenRouter API Key in Streamlit Secrets

Open the existing secrets file:

`project-02-multiturn-conversation/.streamlit/secrets.toml`

Replace the placeholder with your actual OpenRouter API key:

```toml
OPENROUTER_API_KEY = "sk-or-v1-your-actual-openrouter-key-here"
```

> **Security Note:** `.streamlit/secrets.toml` contains sensitive credentials and is explicitly ignored in `.gitignore`. It must NEVER be committed or pushed to GitHub.

### 4. Run the Streamlit Application

```powershell
cd project-02-multiturn-conversation
streamlit run app.py
```

Open `http://localhost:8501` in your browser.

## Learning Takeaway

Conversation context comes from the information provided to the model. In this project, the application maintains the message history and sends the full history with every request.
